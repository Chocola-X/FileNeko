# Upstream Security Audit and Hardening Record

**English** | [简体中文](security-audit-2026-11-15_CN.md)

Audit Date: 2026-11-15. Baseline established following UI refactor `91cdbbfd` against the archived upstream repository. Upstream was archived at version 2.63.23; security advisories cannot be evaluated based on release date alone to determine local applicability.

Audit Sources: [All upstream public security advisories](https://github.com/filebrowser/filebrowser/security/advisories), GitHub public issues, and issue search results. All 62 advisories were retrieved via the GitHub REST API alongside security-related issues; no private reports were accessed and no upstream communications were sent.

Results: 19 advisories corresponded to fixes, permission boundary tightenings, or hardening implemented in this fork; 43 advisories already had appropriate mitigations in place, requiring no duplicate patching. Additionally, the audit addressed the sensitive operation re-authentication gap from #5213, session rotation revocation, file wrapper locks, and share expiration cleanup discovered during regression testing. In the table below, "Pre-existing mitigation" indicates the audit's findings regarding the specific issue and does not constitute a guarantee that the software is free from other vulnerabilities.

## Related Issues

- [#5199](https://github.com/filebrowser/filebrowser/issues/5199): Interactive commands and hooks. Addressed WebSocket message sizing, shell metacharacter injection, hook script interpolation, and non-admin server command permissions. Administrator commands retain the server process's OS privileges; no cross-platform arbitrary command sandbox is provided.
- [#5216](https://github.com/filebrowser/filebrowser/issues/5216): Random, persistent, revocable session identifiers; atomic replacement upon renewal; logout revokes session families; password changes invalidate tokens. JWT is retained as a compatibility envelope for frontend metadata and is no longer trusted on signature alone. Expired records are reclaimed on access/login; maximum 64 active sessions per user.
- [#5213](https://github.com/filebrowser/filebrowser/issues/5213): `f0901a20`. User updates that omit fields or vary sensitive field casing must still verify the current password; global setting writes also require re-authentication. `http/reauth_test.go` covers allow and deny scenarios.
- [#5239](https://github.com/filebrowser/filebrowser/issues/5239): Password shares no longer authenticate via permanent URL tokens; browser downloads use time-limited scoped cookies.
- [#5294](https://github.com/filebrowser/filebrowser/issues/5294): Large text capped at 10 MiB; actual read limits and subtitles patched individually.
- [#5834](https://github.com/filebrowser/filebrowser/issues/5834): Negative Upload-Length is rejected; no duplicate fix needed.
- [#1195](https://github.com/filebrowser/filebrowser/issues/1195), [#1761](https://github.com/filebrowser/filebrowser/issues/1761), [#2570](https://github.com/filebrowser/filebrowser/issues/2570), [#2042](https://github.com/filebrowser/filebrowser/issues/2042): User permission casing bypasses, user info leaks, raw file script execution, and cookie mutations have existing boundaries; verified sensitive operation re-authentication, CSP headers, and non-GET cookie rejection.
- [#1805](https://github.com/filebrowser/filebrowser/issues/1805): Deployments must never place databases or credentials inside file scopes accessible to untrusted users. In this fork, the database stores hashed session identifiers, meaning possessing the JWT signing key alone cannot forge valid user sessions. This does not justify exposing the database.
- [#3900](https://github.com/filebrowser/filebrowser/issues/3900): Auto-provisioning by trusted proxies is expected proxy auth behavior; restricted proxy sources; public signup toggle is not confused with proxy provisioning policy.
- [#5971](https://github.com/filebrowser/filebrowser/issues/5971): Public text stated only that a private report was submitted without verifiable details; no claim of fixing undisclosed vulnerabilities.
- Feature requests, unverified reports, and non-security items (e.g., 2FA, audit logs, quotas, OAuth/LDAP) were not treated as confirmed vulnerabilities.

## Upgrades and Compatibility

- All instances must be upgraded simultaneously; existing tokens are invalidated, requiring re-login. JWT remains for frontend compatibility; the server validates revocable sessions in the database on each request.
- Interactive Execute grants to non-administrators are disabled. Interactive commands do not use a global shell; hook variables are passed via the environment rather than expanded into arguments/scripts.
- Proxy authentication trusts only loopback by default. Configure `--auth.trustedProxies=IP/CIDR` for remote/container proxies, and overwrite client headers. See [Authentication documentation](authentication.md).
- Legacy token download URLs for password-protected shares are invalid. Entering the password unlocks downloads in that browser via a cookie valid for up to 1 hour. Public unpassworded shares retain public behavior.
- Public signup always creates a dedicated isolated home directory. Existing account scopes and file permissions are not migrated automatically to prevent unexpected changes to user data; administrators should review existing accounts.
- TUS uses OS-level file locking on scoped files; verified on Linux using real wrapped files. Windows cross-compilation verified (not tested on Windows); platforms without locking support reject lock operations. Shared storage backends must support standard OS file locking semantics.
- Password guessing limits track real source addresses, grouping IPv6 by `/64`. Proxied users share a budget unless trusted proxies are configured. Limits are process-local; multi-instance setups should implement complementary cluster-level rate limiting on trusted reverse proxies.
