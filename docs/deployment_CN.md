# 部署 FileNeko

[English](deployment.md) | **简体中文**

FileNeko 可以管理其服务端进程有权访问的所有文件。请将其作为敏感服务对待，而非普通的静态文件公开站点。这是一个按“尽力而为”原则维护的个人项目，并非经过严格安全审计的商业托管平台。

## 推荐的安全基线

- 以非特权系统用户运行 `fileneko`，且仅赋予其对目标文件目录及其数据库/配置文件的访问权限。
- 切勿将应用直接暴露在公网中。请将其置于启用了 HTTPS 的反向代理之后，并配置适当的访问控制或额外的身份验证层。
- 除非确实需要并愿意承担相应风险，否则请**保持命令执行功能处于禁用状态**；详见[命令执行](command-execution_CN.md)。
- 在升级前备份文件数据、数据库及配置文件。避免将数据库文件公开或共享敏感日志。
- 审阅 [SECURITY_CN.md](../SECURITY_CN.md) 与[安全核查记录](security-audit-2026-11-15_CN.md)。核查记录并非绝对安全的保证。

本项目目前**尚未发布官方 FileNeko Docker 镜像**。请使用[独立可执行文件](installation_CN.md)或源码编译；上游 File Browser 的镜像并不等同于本项目。

## 自助注册

自助注册功能可在**设置 → 全局设置**中配置，或通过 `fileneko config set --signup` 开启。新注册的用户将继承所配置的用户默认设置与范围（Scope）。**在启用注册前务必审查这些默认设置**：否则新用户可能会获得超出预期的访问范围。

FileNeko 提供了 `createUserDir` 选项为每个用户创建专属目录。无论是否开启该选项，都应核对安装环境的实际默认范围、用户权限及文件系统归属。如果不需要公开注册，请保持该功能关闭。

## 登录保护与反向代理

与旧版 File Browser 文档不同，FileNeko 针对连续失败的密码尝试提供了**内置的临时登录封禁机制**，同时覆盖网页登录与 WebDAV Basic 身份认证。默认规则为 5 分钟内连续失败 5 次即触发 5 分钟临时封禁。这些选项可在**设置 → 全局设置 → Fail2Ban · 登录保护**中管理。详见 [WebDAV](webdav_CN.md#防止密码暴力破解)。

默认情况下，应用程序直接使用网络连接的对端 IP。在反向代理后运行时，请**谨慎**配置受信任的代理地址，并确保代理覆盖客户端传递的转发头。否则，处于同一代理后的所有用户可能会共用封禁配额，而盲目信任任意转发头会导致基于 IP 的限流完全失效。当前 Nginx 配置示例请参阅 [reverse-proxy_CN.md](reverse-proxy_CN.md)。

内置的限流与封禁仅在当前进程内存中维护，不能取代代理层防护或适当的外层认证。多个服务实例之间不会自动共享内存中的封禁列表。

### 可选的外部 Fail2ban

您仍然可以使用外部系统级 fail2ban 进行额外的主机级过滤，但这**并非** FileNeko 内置登录保护的前置必要条件。如果配置外部 fail2ban，请在实际部署中测试验证日志格式和源 IP 处理，切勿未经测试直接套用旧版上游 File Browser 的正则表达式。
