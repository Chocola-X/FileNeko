# 文件夹信息统计

打开当前目录或选中文件夹的“信息”弹窗，即开始递归统计文件总大小、文件数量和子文件夹数量。较长的扫描大约每 500 毫秒更新一次累计值，结束后显示“统计完成”；无需提前计算全部项目数量，也不显示无法确定的百分比。多选中包含文件夹时，会串行扫描各文件夹并合计选中的普通文件。

## 生命周期与存储

- 关闭弹窗、按 Escape、点击背景、切换弹窗或离开页面时，前端通过 `AbortController` 中止请求；停止按钮也可取消统计并暂时保留当前累计值。
- 后端使用该 HTTP 请求的 context，在目录操作前和各项目之间检查取消状态，停止遍历并关闭已打开的目录句柄。正在执行的底层文件系统调用无法被 Go context 强制打断，在调用返回后退出。
- 每个服务实例最多同时运行两个扫描；其余请求等待，并发送等待状态心跳。等待中的请求同样可以取消。
- 结果仅在当前请求和弹窗内存中存在，不建立磁盘缓存、不写统计数据库、不生成临时文件。重新打开会重新扫描，不沿用之前的结果。响应使用 `Cache-Control: no-store`。

## 统计口径

- 大小是文件长度的合计，不是磁盘实际占用；稀疏文件、压缩或共享数据可能导致两者不同。硬链接按每个文件目录项分别计入。
- 计入有权访问的隐藏文件，不受列表的“隐藏点文件”显示选项影响。服务器及用户访问规则仍然生效，被规则排除的子树不会统计。
- 不跟随或计入符号链接，包括符号链接形式的扫描根目录，避免重复统计和循环。
- 单个文件夹不把根目录自身计入子文件夹数量；多选时计入选中的文件夹根目录。
- 读取失败时保留可取得的累计值，标明结果不完整。连接异常或提前结束也不会显示为统计完成。扫描期间目录可能发生变化，结果不是文件系统快照。

## 接口和部署

`GET /api/directory-stats/<path>` 使用与文件列表相同的登录认证，返回 `application/x-ndjson`。路径相对于用户范围；服务部署在子路径时，前端沿用现有 BaseURL。独立的接口路径避免与名为 `stats` 的普通文件夹发生路由冲突。

每行是累计状态，例如：

```json
{"size":1048576,"numFiles":12,"numDirs":3,"incomplete":false,"done":false,"queued":false}
```

`done: true` 表示扫描结束，`incomplete: true` 表示部分项目读取失败；`queued: true` 表示等待扫描名额。客户端应将缺少结束标记的响应视为中断，并在关闭信息窗口时取消整个 fetch 请求及其响应流。

接口只读取元数据，使用每批最多 256 个项目的无排序目录枚举，不进行类型检测、文件内容读取或预览生成，也不将完整目录树传给客户端。

响应包含 `X-Accel-Buffering: no`，让 Nginx 转发累计结果而不缓冲。代理应保持默认的 `proxy_ignore_client_abort off`，且不应忽略 `X-Accel-Buffering` 响应头；否则关闭浏览器请求后，代理可能继续维持后端扫描，或无法及时显示进度。
